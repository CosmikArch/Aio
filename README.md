# play

A terminal music player written in Go. Streams audio from YouTube via `yt-dlp` and plays it through `mpv`. Supports local caching, a queue system, background daemon processing, and an interactive TUI. The cache layer is a Rust library linked into Go via CGO.

## Requirements

| Dependency | Purpose |
|---|---|
| `yt-dlp` | Audio extraction from YouTube |
| `mpv` | Playback |
| `ffmpeg` | Format handling and metadata tagging |
| Go 1.21+ | Main application |
| Rust 1.75+ | Cache library (`play-cache`) |

All runtime binaries (`yt-dlp`, `mpv`, `ffmpeg`) must be on `PATH`.

## Usage

```bash
play "song name"           # Search and play
play <youtube-url>         # Play by URL
play tui                   # Interactive TUI
play stop                  # Stop playback and daemon
play recent                # Playback history
play fav                   # List favourites
play fav add "query"       # Add to favourites
play queue add "query"     # Enqueue a track

play cache stats           # Aggregate cache statistics
play cache list            # List cached entries
play cache search <query>  # Search cache
play cache export [file]   # Export metadata to JSON
play cache tag [--dry-run] # Embed tags into cached files
```

## Architecture

```
cmd/play                → CLI entry point and dispatch

internal/cli/parser     → command parsing and flag handling
internal/resolver       → source classification (cache vs. network)
internal/player         → mpv control, daemon, playback lifecycle
internal/cache          → Go-side cache interface; delegates to play-cache via CGO
internal/queue          → queue management
internal/favorites      → favourites persistence
internal/history        → playback history
internal/tui            → interactive terminal UI
internal/ui             → terminal output utilities
internal/config         → paths, initialisation, keybindings
internal/youtube        → yt-dlp integration
internal/locks          → download locking and concurrency control

play-cache/             → Rust cache library (cdylib + CLI binary)
  src/lib.rs            → C ABI surface
  src/cache/index.rs    → lookup, stats, add (pure; no IO)
  src/cache/store.rs    → load/save  (~/.play/cache.json, atomic)
  src/model/mod.rs      → CacheEntry, Stats
  src/parser/json.rs    → stdin/stdout JSON protocol
  src/error/mod.rs      → error type
  play_cache.h          → generated C header (cbindgen)
```

### Cache FFI boundary

Go calls the Rust library through CGO via five functions. The surface is intentionally narrow: no shared structs, no nested pointers, no cross-runtime allocator interaction.

```c
CacheHandle *cache_open(void);
char        *cache_get(const CacheHandle *handle, const char *query);
int          cache_put(CacheHandle *handle, const char *entry_json);
void         cache_free_string(char *s);
void         cache_close(CacheHandle *handle);
```

Rust owns all allocations. Strings returned by `cache_get` must be released with `cache_free_string`; handles must be released with `cache_close`. The `CacheHandle` layout never crosses the boundary — Go holds an opaque pointer.

`play-cache` also builds a standalone CLI binary that speaks the same JSON protocol over stdin/stdout, useful for testing the cache layer independently.

### Runtime flow

1. CLI parses input and constructs a structured command.
2. Resolver classifies the request (cache hit or network fetch).
3. Player or queue system executes playback.
4. Cache stores metadata and media for future use.
5. Daemon processes background jobs asynchronously.

## Build

The Rust library must be built before the Go binary.

```bash
# 1. Build the cache library
cd play-cache && cargo build --release && cd ..

# 2. Build the Go binary (CGO_ENABLED=1 is the default)
go build -o play ./cmd/play
```

```bash
# Cache library only
cd play-cache && cargo build --release
# → target/release/libplay_cache.so   (Linux)
# → target/release/libplay_cache.dylib (macOS)
# → play_cache.h  (auto-generated by cbindgen)

# Run Rust unit tests
cargo test

# Cross-compile Go for Windows (experimental)
GOOS=windows GOARCH=amd64 go build -o play.exe ./cmd/play
```

## Notes

- Linux is the primary target. Windows support is experimental; TUI behaviour may vary across terminals.
- The cache file is stored at `~/.play/cache.json` and written atomically by the Rust layer.
- The Rust cdylib is expected at `play-cache/target/release/` when linking the Go binary.
